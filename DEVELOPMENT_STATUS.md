# Development status — GhostState 0.2.2

Last updated: 19 November 2026. Verification environment: Debian 13 x86-64, Node 20.20.2, Chromium for Testing, Firefox 159 and Rust; Windows binaries were cross-compiled on Linux. This is an **unsigned, unaudited prototype**, not a production password manager. Use synthetic credentials until independent security review and target-platform testing are complete. See [BUILD_ERRORS.md](BUILD_ERRORS.md), [TASKS.md](TASKS.md) and the [Chrome release guide](docs/CHROME_STORE_RELEASE.md).

## Implemented and bounded

| Area | Current implementation and limits |
|---|---|
| Extension UI | The supplied emblem and upgraded responsive dashboard, popup, font and icons are packaged locally. No separate server is needed or included in the Chrome extension. A separate static web-only preview is packaged and clearly labeled; it cannot use extension or Bluetooth features. Desktop-engine viewport and keyboard/touch emulation passed; there is no Android or iPhone app. |
| Local vault | IndexedDB whole-vault AES-256-GCM, 600,000-iteration PBKDF2-SHA-256, random salts/nonces, lock/idle timeout, encrypted backup/restore, 200-profile cap and optional local activity logging. A lost master passphrase cannot be recovered. |
| Password tools | Configurable local generator; search, edit and reauthenticated reveal/copy; basic offline reused/weak-pattern warnings; explicitly reviewed, bounded standard/Bitwarden login CSV import. It is not a breach detector, passkey manager or full importer. Source CSV files may be plaintext. |
| Workflows | Explicitly grant/select a site, scan value-free structural descriptors, map fields and manually approve filling. Automatic fill is off by default, selected-profile/tab-only and valid at most ten minutes. No form submission, OTP solving, automatic cross-origin SSO, iframe or shadow-DOM mapping. A selected site can read anything filled. |
| Native host | Optional exact-caller native messaging. The Linux x86-64 and Windows x64 binaries are separate, unsigned development artifacts. Windows caller registration logic was exercised using mocked PowerShell on Linux, and native framing/caller checks ran under Wine; those are not actual Windows OS tests. |
| Nearby sharing | Experimental `btleplug` central on Linux/Windows/macOS source; Linux/BlueZ and new Windows/WinRT GATT receiver implementations. BLE v2 uses session-only X25519/HKDF/AES-GCM, user-compared eight-digit codes, authenticated confirmations and short-lived grants. Sender has eight software slots; Linux/Windows listener admits one owner until stopped. No physical radio transfer or adapter capacity has been verified. macOS has no receiver/binary supplied, and mobile companion apps do not exist. |
| Cloud | No GhostState cloud service, automatic sync or remote recovery. Users may manually export an encrypted backup and upload it themselves; restore needs the original passphrase and replaces rather than merges the current vault. |
| Store preparation | A root-manifest Chrome ZIP, developer-unpacked archive, Store screenshots/icon, draft privacy and listing text, reviewer instructions and separate companion packages are prepared. Nothing has been uploaded, published or reviewed by Google. The publisher must provide a public policy URL, contacts and any companion download, and verify current policy compliance. |

## Most recent verification

All tested credentials were synthetic. Some end-to-end automation uses test-only pregranted permissions; separate prompt tests use the unmodified shipping manifests.

- `npm run build` passed TypeScript and generated Chromium/Firefox Manifest V3 bundles. `npm test` passed **28** unit/security tests, including checks that the bundled native bridge is not web-accessible.
- `npm run test:dashboard` passed password tools, explicit CSV review/import, local branding, empty/locked states, responsive interactions, activity controls and encrypted backup/restore. The earlier focus-stealing bug is covered by a deterministic regression.
- `test:responsive` passed 22 populated and six fresh/locked Chromium viewport sizes; `test:responsive:firefox` and `test:responsive:webkit` passed nine representative emulated sizes each, both themes and keyboard/focus. These are desktop-engine emulations, not real phones or a Safari extension.
- `test:a11y` passed **103** automated axe-core checks across layouts, dialogs, themes and popup; manual accessibility review remains required.
- `test:browser`, `test:autofill` and `test:permission` passed Chromium synthetic two-step learning/fill, permissions, origin/port isolation, opt-in and off-by-default autofill safeguards, restart persistence and an actual Linux native-host connection. The consent prompt test used the unmodified extension.
- `test:native-permission` used the real Chromium optional prompt and registered Linux host to check denial, missing-host guidance, acceptance, reconnection and active permission revocation. In a stale worker it also checks the one-use, tab-bound local bridge, wrong-token/wrong-tab/replay rejection and dashboard-close lifecycle. `test:native-bridge` used the real prompt with a **mock host** to check cancelled/approved synthetic transfers to two peers, incoming acceptance and locked-vault denial. Neither tests physical BLE.
- `test:native-ui` exercised missing-host guidance, displayed installed ID, capability gating and focus retention using a synthetic host. `test:native` and `test:installer` passed Linux framing, caller/schema restrictions, exact-ID registration, self-copy, file modes and malformed-input handling.
- Firefox synthetic workflows and actual registered Linux native host passed; real site/native/authentication-info prompts were exercised on the unmodified package. Transfer UI used a **mock** native peer, not BLE.
- The optional public demo smoke test filled its published fake credentials on a third-party practice form using a test-only pregrant; it did not submit the form. The demo site may change or become unavailable.
- Rust fmt and Linux/Windows-target Clippy passed with `-D warnings`; **14** Linux Rust tests and **14** Windows-target tests under Wine passed. Release binaries were rebuilt after the latest changes and compared with their staged copies. The Windows EXE passed caller, native-framing and invalid/unpaired-command checks under Wine. PowerShell installer/diagnostic tests used mocked registry functions on Linux. These results are not real Windows or radio testing.
- `npm audit` returned zero vulnerabilities; OSV queried **194** exact Cargo.lock crates with zero advisory matches. Firefox `web-ext lint` reported zero errors and three dynamic-`innerHTML` warnings; escaping and CSP do not replace review.
- `test:release` exercised the exact extracted Store ZIP and the separately packaged static preview, including its sample-data warning, local-only assets and unavailable native connection. It checked every archive inside the complete package and verified both nested checksum lists. The preview remains separate from the extension vault.
- Four actual-extension screenshots were captured using synthetic profiles, with no external HTTP requests observed on the dashboard page, at 1280×800 RGB; the Store icon is 128×128 RGB. The experimental Bluetooth screenshot makes the limitation visible. The self-contained HTML guide was rendered as a four-page tagged PDF with no footer overlap.

## Release and remaining gates

The Chrome Store ZIP is extension-only and has `manifest.json` at its root. The developer kit and complete package are convenience archives, **not** Store uploads; extract them and use only the nested Chrome Store ZIP for a Store draft. The complete package also includes source, the experimental Firefox build, a standalone static preview and deployment instructions. SHA-256 checksums detect corruption, not publisher identity. The source project retains an optional Vite development workspace for tests; it is not shipped in the extension.

No hosted CI run, real Windows installation, physical Bluetooth transfer, real mobile test, macOS build, Safari native bridge, independent cryptographic/security review or production signing has been completed. `tests/integration/windows-real.mjs` is a Windows-only disposable CI test definition and has **not** been run. Do not describe any radio route, mobile support, store approval or security audit as complete. See [Bluetooth test plan](docs/BLUETOOTH_TEST_PLAN.md).
