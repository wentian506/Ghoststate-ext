# Release notes

## 0.2.2 — Chrome developer package and experimental Windows receiver

- Preserves the upgraded emblem, responsive dashboard, popup, vault, scoped workflows and opt-in autofill. The Chrome Store ZIP contains only the built extension with a root manifest; no standalone server or old branding is included. Separate developer-unpacked, Store-listing, unsigned companion and source packages are available. A clearly labeled static web-only preview, deployment guide and complete convenience package are also supplied; the preview has separate data and cannot use extension or Bluetooth features.
- Adds an experimental Windows WinRT GATT peripheral sharing the bounded, single-owner transport with the Linux receiver. The Windows EXE was cross-compiled and protocol-tested under Wine; actual Windows OS installation, callbacks, permissions, advertising and all physical Bluetooth routes remain untested. macOS has no receiver, and Android/iPhone apps do not exist. Use only synthetic credentials.
- Improves native disconnect/timeout handling, exact extension-ID setup guidance, Windows installation/diagnostics, Linux installer validation and adapter error reporting. If Chrome's already-running worker lacks `connectNative` after an optional grant, a one-use, tab-bound bundled frame relays the local host connection; keep the connecting dashboard open. A real Chromium prompt and registered Linux host were tested, with synthetic transfer routing checked separately using a mock. Neither test validates Bluetooth. The dashboard reports implementation capabilities without presenting them as proof of radio support.
- Adds actual-extension synthetic screenshots, draft listing/permission/reviewer materials, a privacy-policy template and hardware test plan. A publisher must supply real contacts, host and legally review the policy, provide a companion download, verify Store disclosures and complete independent security and real-device tests before submission. No upload or Store approval occurred.
- Verification: 28 TypeScript tests, 14 Linux Rust tests, 14 Windows-target Rust tests under Wine, Linux/Windows-target Clippy, Chromium/Firefox synthetic workflows, real optional permission prompts, responsive emulations and 103 automated axe checks passed. Mocked registry/Wine testing is not Windows or Bluetooth validation. Hosted CI and independent review remain outstanding.

## 0.2.1 — interface refresh and dialog-focus fix

- Replaces the dashboard, favicon, popup, extension icons and guide branding with the newly supplied geometric emblem. The unmodified original remains in `apps/dashboard/assets/ghoststate-logo-original.png`.
- Adds a responsive bottom navigation and **More** menu for narrow or short viewports, compact landscape layouts, touch-sized controls, safe-area spacing and scrollable dialogs. The desktop keeps the dark sidebar and reference-inspired warm, bordered cards. Both light and dark themes remain available.
- **Security-relevant correction:** 0.2.0 used deferred initial dialog focus. If a user selected a different field and began typing before that callback ran, focus could move back to the profile-name field, causing sensitive typed text to be saved as a visible profile name. The dialog now sets initial focus synchronously, before control returns to the user. A deterministic regression test fails against the old implementation and passes against the fix; 30 additional synthetic edit iterations passed. This is not an independent security audit.
- If an older build was used, inspect profile names for accidentally entered secrets. If a website password appeared there, treat it as exposed and change it on that website; update any affected saved credential as appropriate. If a master passphrase appeared there, treat that vault and its backups as compromised and migrate to a new vault with a new passphrase; there is no in-place master-passphrase change or recovery service. Do not use real credentials with this unaudited prototype.
- Retains the 0.2.0 vault format, password tools, off-by-default scoped autofill and BLE protocol v2. A web preview has separate storage from the browser extension and cannot inspect tabs or connect the Bluetooth companion.

Chromium, Firefox and WebKit desktop-engine viewport/touch emulation passed on representative sizes. This is **not** a real-phone test, a mobile-extension implementation, Safari extension validation, or a physical Bluetooth test. The packages remain unsigned and unaudited.
