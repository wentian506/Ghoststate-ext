# GhostState compared with established password managers

Research checked 19 November 2026 against the vendors’ documentation linked below. Features and plan availability can change. This is a practical comparison, not a security audit or a claim that products use identical designs.

| Capability | Examples in established products | GhostState 0.2.2 prototype |
|---|---|---|
| Save and fill logins | 1Password and Proton Pass offer to save logins and provide browser fill suggestions [1](https://support.1password.com/getting-started-browser/) [3](https://proton.me/support/pass-browser-extension). Bitwarden supports user-selected methods and optional page-load fill [1](https://bitwarden.com/help/auto-fill-browser/). | Manually add or import a login, explicitly select its exact site, and teach its visible top-frame sign-in steps. Review and fill each step, or opt in to automatic fill for **one profile and one selected, focused tab for up to 10 minutes**. It is off by default and stops on lock, disable, target reselection, permission revocation, worker restart or expiry; navigation away to a different origin pauses filling. No automatic form submission. |
| Capture newly created or changed passwords | 1Password and Proton offer save/update prompts [1](https://support.1password.com/getting-started-browser/) [1](https://proton.me/support/proton-pass-autosave). | **Not implemented.** Enter or import the login deliberately; editing GhostState does not change the website’s password. |
| Password generator | Bitwarden, 1Password and Proton provide configurable generators [3](https://bitwarden.com/help/generator/) [1](https://support.1password.com/getting-started-browser/) [3](https://proton.me/support/pass-browser-extension). | Local Web Crypto generator in Add/Edit with length and character-set options. No passphrase generator or generator history. |
| Search, edit, copy | Common features in established tools. | Search profile name/site; edit after re-entering the master passphrase; reveal/copy after reauthentication. Clipboard history may retain copied data. |
| Import and backups | Established products offer multiple import/export formats. | Local, explicitly reviewed CSV import of `url,username,password` plus optional `name`, or Bitwarden’s `login_uri,login_username,login_password` login columns. Unsupported/incomplete rows are skipped; exact origin/username duplicates are skipped. 200 profiles maximum. Encrypted JSON backup/restore; no merge. OTP seeds, notes, passkeys and other CSV fields are not imported. |
| Password health / breaches | 1Password Watchtower offers broader security reports [1](https://support.1password.com/getting-started-browser/). | Basic **offline** warnings for reused passwords and some simple weak patterns. No breach database, compromised-password lookup or guarantee that an unflagged password is strong. |
| Passkeys and two-factor codes | 1Password supports storing/using passkeys and generating one-time codes [1](https://support.1password.com/getting-started-browser/) [5](https://support.1password.com/one-time-passwords/). | **Not a passkey manager or authenticator.** Complete passkeys, OTPs, CAPTCHA, security questions and hardware-key checks yourself. Deliberately does not capture or store one-time codes or seeds. |
| Sharing | Examples include 1Password shared items and Proton shared vaults with access controls [1](https://support.1password.com/getting-started-browser/) [2](https://proton.me/support/proton-pass-for-business-user-guide). | Experimental Bluetooth credential transfer only. A sender can hold **up to eight software connection slots**, each with a separately compared eight-digit code and explicit per-recipient send; a Linux or experimental Windows receiver handles one sender session and up to eight pending grants at a time. Physical radio behavior and actual concurrent connection capacity are untested and may be lower. This is not a shared vault, broadcast, or revocable password grant; once imported, a password remains usable until changed at its website. |
| Cloud sync and recovery | Bitwarden offers cloud sync and a self-hosted option [5](https://bitwarden.com/help/password-manager-plans/). | **No GhostState cloud service or automatic sync.** A user may manually upload a GhostState-encrypted backup to their own storage and restore it with the original master passphrase. No remote recovery or conflict merge. See [cloud instructions](CLOUD_BACKUP_AND_SYNC.md). |
| Platforms and maturity | Proton, for example, documents browser extensions and iOS/iPadOS and Android apps [5](https://proton.me/support/pass-setup-ios). | Chromium and Firefox synthetic workflows were tested on Linux. There is no mobile app; Safari’s native bridge is incomplete; Windows/macOS and physical Bluetooth have not been verified. No independent security audit, signing, hosted CI run or production support. |

## Why automatic fill is limited

An unlocked website can read anything inserted into its own form. A compromised or malicious site can exploit automatic filling, even when its origin matches; exact-origin checks are not proof that a site is trustworthy. Bitwarden’s documentation likewise says page-load autofill is off by default because compromised or untrusted sites could steal credentials [1](https://bitwarden.com/help/auto-fill-browser/). GhostState’s opt-in also requires a previously learned exact structural state, no detected challenge, a visible/focused top-level page, empty target fields and a same-origin form action. These are risk reductions, not guarantees. A site may react to input events or submit on its own; the GhostState code does not submit forms.

## Still needed before claiming full parity

- Independent cryptography, extension security, privacy, accessibility and penetration reviews; signed releases, a production add-on ID and a real support/incident process.
- Real BLE hardware testing with several receivers, failures, congestion, adapter limits and cross-platform lifecycle tests; native receivers for Windows/macOS if required.
- A separately designed and audited end-to-end encrypted cloud sync service with device enrollment, conflicts, recovery and rollback handling.
- Save/update prompts, unlearned-site inline suggestions, mobile and Safari support, passkey integration, secure notes/cards/identities, richer import formats, breach monitoring, biometric unlock and shared-vault administration. These are **not** included here. One-time-code storage is deliberately excluded by the project’s privacy requirements.

## CSV format references

The standard import column names correspond to the `url`, `username` and `password` headers documented by Google [1](https://support.google.com/chrome/answer/13068232?hl=en&co=GENIE.Platform%3DDesktop); Bitwarden documents its `login_uri`, `login_username` and `login_password` headers [1](https://bitwarden.com/help/condition-bitwarden-import/). GhostState supports only the limited login fields and conditions described above, not full fidelity import.
