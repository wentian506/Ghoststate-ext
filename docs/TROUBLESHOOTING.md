# Troubleshooting

- **The dashboard says “Local web workspace”**: you are viewing the standalone Vite preview. It cannot access other tabs or the companion and has separate IndexedDB. Install/load the browser extension and use its toolbar popup.
- **Site cannot be selected**: use HTTPS, or loopback HTTP for local testing. Open the exact URL first, then click the GhostState toolbar icon and approve the permission. Restricted browser pages, file URLs, other HTTP sites and mobile captive-portal mini-browsers are not supported.
- **“Origin mismatch” after redirect**: scheme, host *and port* must match the profile and selected tab. Cross-origin SSO is not followed automatically. Select the new origin and explicitly use a separate profile; never copy a cookie.
- **No eligible fields or page changed**: only visible top-frame standard inputs are mapped. Shadow DOM, embedded frames and custom controls are not implemented. Capture again after the page settles; a changed path or layout can require re-learning. Unknown screens and detected challenges intentionally pause.
- **CAPTCHA/OTP/passkey/security question**: complete it yourself. Detection is heuristic; if the software fails to detect one, do not map or fill it. No challenge is solved and no one-time code is captured by GhostState.
- **Automatic fill does nothing**: it is off by default. Confirm you explicitly enabled it for the selected profile and tab; return to that focused tab while unlocked. It requires a learned exact state, visible empty fields, no detected challenge and a same-origin form action. It stops on lock, permission revocation, worker restart or ten-minute expiry. Use Review & fill or sign in manually when needed.
- **CSV row was skipped**: GhostState requires an HTTPS URL (loopback HTTP only for tests), username and password, and a supported standard or Bitwarden login header. Notes, OTP fields, non-login items and incomplete or unsupported URLs are not imported; exact origin/username duplicates are skipped. The vault limit is 200 profiles. CSV exports are usually plaintext and must be handled carefully.
- **Vault re-locks quickly**: MV3 may suspend/restart the background worker, clearing its key earlier than the configured idle timeout. Unlock again. Keep the master passphrase safe; there is no provider recovery. Restore a backup only with its original passphrase.
- **Lost passphrase**: encrypted data cannot be recovered. If you have a backup and its passphrase, delete/reset the current vault, then choose **Restore it instead** during setup. A reset permanently removes the current vault.
- **“Specified native messaging host not found”**: verify the browser-specific manifest path, executable path and exact installed extension ID, then rerun the installer and restart the browser. Chrome for Testing with a custom user-data-dir can use `<user-data-dir>/NativeMessagingHosts` instead. Check host stderr via browser debugging logs; do not log credentials.
- **“Unauthorized native messaging caller”**: ensure the browser host manifest and `~/.config/ghoststate/allowed-callers.json` (Windows: `%USERPROFILE%\.config\ghoststate`) contain the *same exact* trusted ID/origin. Unix config must not be group/other writable. Firefox passes its add-on ID, not a Chromium origin.
- **Activity log is empty**: logging is off by default. Unlock the vault and enable it under Privacy & security; only future authorized operations are logged.
- **No Bluetooth adapter / D-Bus**: start BlueZ and D-Bus, grant OS Bluetooth permissions, power the adapter on yourself and retry. Discovery requires a second device already listening. Receiver code exists for Linux and experimental Windows but neither has been physically validated; macOS has no receiver, and no Android/iPhone app exists. The sandbox used to develop this project had no adapter; hardware behavior remains unverified.
- **A new sender cannot connect**: the receiver reserves its current listener for the first peer, even after that peer disconnects. Stop listening and start discovery again. An untrusted nearby sender can occupy the slot, so denial of service remains possible.
- **Pairing code differs or expires**: reject/end pairing, use a trusted comparison channel, and start a new discovery. Both devices must use v2/eight-digit protocol; older companions are not compatible. Confirm both sides within two minutes; on sender press **Check other device** after the receiver confirms. Do not approve mismatched codes.
- **Transfer expired**: the recipient must review and accept within 120 seconds; check device clocks. A new user-approved transfer is required. Pending grants are memory-only and disappear when the listener stops or the host exits.
- **Safari**: conversion requires Xcode on macOS. Its native app-extension handler is not implemented here, and Safari/native Bluetooth is not tested. OS captive portal mini-browsers do not run these extensions.
